# 经验沉淀：renamer-web 的踩坑与平台限制

本文件记录重构 `ReNamer 7.3` 为本地 Web 宿主过程中，实际踩到并解决的问题。
每条都注明**现象 → 原因 → 做法**，便于以后同类项目直接复用。

> 其中跨项目可复用的部分（启动链契约、浏览器复用、DPI 对话框、两阶段改名、游标分页、
> CDP 验收）已抽取为技能 `windows-local-web-shell`；本文件保留本项目特有的路径、数字与决策记录。

---

## 1. SSE 常开连接会让 headless 截图永远挂住

**现象**：`msedge --headless=new --screenshot=... http://127.0.0.1:8758/` 执行 120 秒不退出，也不产出 PNG。

**原因**：`--screenshot` 等的是「页面加载完成（network idle）」。本应用有一条常开的
`EventSource('/api/events')`，连接永不结束，`network idle` 永远不成立。

**做法**：改用 CDP 驱动（`--remote-debugging-port=9222` + `Page.captureScreenshot`），
或给页面加一个可关闭 SSE 的开关。CDP 还顺带能读 DOM 指标，比截图更可验证。

---

## 2. PowerShell 5.1 读无 BOM 的 `.ps1` 会按 ANSI 解析

**现象**：脚本里的中文 `Write-Host` 输出乱码；极端情况下引号被 ANSI 字节序列撑破，报
`字符串缺少终止符`。

**原因**：Windows PowerShell 5.1 对**没有 BOM** 的脚本按当前 ANSI 代码页解码，而不是 UTF-8。
由 `start.cmd` 拉起的 `powershell.exe` 正是 5.1。

**做法（最终选择）**：`start.cmd` 与两个 `.ps1` 全部写**纯 ASCII**，中文只出现在页面和 Node 脚本里——编码问题从根上消失，双击后也不会出现乱码。校验方式：读字节，确认没有 ≥ `0x80` 的字节。

**例外**：`picker.mjs` 运行时生成的临时脚本仍前置 `\ufeff`，因为它要经 `-File` 执行，且未来可能加入中文提示。

**若坚持在 `.ps1` 里写中文**：必须存成 **UTF-8 with BOM**，否则 5.1 按 ANSI 解码。
校验：`[System.IO.File]::ReadAllBytes($f)[0..2] -eq 0xEF,0xBB,0xBF`。

## 3. scriptblock → delegate 强转在 try 块里解析脆弱

**现象**：`Add-Type` 之后写 `$cb = [RwWindow+EnumWindowsProc] { ... }`，PowerShell 解析器报
「字符串缺少终止符 / 缺少右 }」，错误位置还落在几十行之后。

**原因**：委托强转 + `try { }` + 内部 `param()` 的组合让解析器状态跑偏，报错点与真实原因错位。

**做法**：把 `EnumWindows` 的遍历逻辑整体放进 **C# 侧**（`Add-Type` 里写静态方法
`FindVisibleByTitle` / `Activate`），PowerShell 只调两个静态方法。代码更短，也不再依赖
PowerShell 的委托转换规则。

---

## 4. `direction: rtl` 会重排以点开头的路径

**现象**：目录列显示 `E:\test\renamer-web\...`，而真实路径是 `E:\.test\renamer-web\...`，
开头的点被 bidi 算法搬到了末尾。

**原因**：`direction: rtl` 为「显示路径尾部」而设，但 `.` 与 `\` 在 RTL 上下文里会改变视觉顺序。

**做法**：目录列固定 `direction: ltr`，靠 `text-overflow: ellipsis` 截尾。需要对路径做
Unicode 双向文本处理才是真解，但代价远大于收益。

---

## 5. Node 没有 Win32 文件属性 API

**现象**：需要按「隐藏 / 系统」过滤，但 `fs.stat` 只给 mode，没有 `FILE_ATTRIBUTE_HIDDEN`。

**做法**：只有用户真的取消勾选「包含隐藏/系统」时，才用**一次** PowerShell 预扫描
（`Get-ChildItem -Force -Recurse` + `Attributes -match Hidden`）建立路径集合；默认全含时
零成本。预扫描失败就**放行**而不是隐藏文件（fail-open），避免误判成「文件消失」。

---

## 6. NTFS 上「只改大小写」的重命名是空操作

**现象**：`rename('Case.txt', 'case.txt')` 在 Windows 上不报错也不生效。

**原因**：NTFS 大小写不敏感但保留大小写，API 判定为同一路径。

**做法**：两阶段提交——先改到唯一临时名 `.__rn_tmp_xxxx`，再改成目标名。两阶段同时解决了
A↔B 互换时的覆盖问题（第一阶段把所有源名先腾空）。

---

## 7. 长路径必须补 `\\?\`

**现象**：深层目录重命名报 ENOENT / ENAMETOOLONG。

**做法**：`toLongPath()` 在长度超过阈值且是绝对路径时前置 `\\?\`，UNC 路径用 `\\?\UNC\`。
阈值取 250（不是 260），给 8.3 名称和末尾分隔符留余量。

---

## 8. 浏览器拿不到拖拽文件的绝对路径

**现象**：`DataTransfer.files[i].path` 在普通标签页里是 `undefined`。

**原因**：Chromium 出于安全不暴露本地路径（Electron 曾提供，普通页面没有）。

**做法**：不假装支持拖拽。`drop` 时明确提示改走「添加文件 / 添加目录」，由宿主弹出原生对话框。
**不要**用 `--user-data-dir` 或 `--app=` 去换取路径能力——那会带来独立 Profile、LocalStorage
丢失与僵尸进程（见第 9 条）。

---

## 9. 复用系统浏览器，不要另起 Profile

**做法**：`Start-Process http://127.0.0.1:8758/` 走 ShellExecute，用默认浏览器普通标签页打开。
想「复用已开窗口」就按窗口标题枚举（见第 3 条），而不是靠独立 user-data-dir。

**理由**：独立 Profile = 全新 LocalStorage（预设、上次目录全丢）+ 扩展冲突 + 关标签后
进程残留。这些都是真实用户能立刻感知的退化。

---

## 10. 启动链：退出码、身份嗅探与日志

`start.cmd` 只做三件事：`where node` 守卫 → 隐藏运行 `launch-server.ps1` → 隐藏运行 `open-app.ps1`。

**退出码是 `cmd` 与 `ps1` 之间的契约**（照搬 xiaowan-web，`start.cmd` 按 3→2→1 顺序判断）：

| 码 | 含义 | `start.cmd` 的反应 |
|---|---|---|
| 0 | 宿主已在跑，或刚启动成功 | 继续开浏览器 |
| 1 | 宿主没起来 | 指向 `.tmp\logs\server.err.log` 并暂停 |
| 2 | 端口被别的程序占用 | 提示改 `config.json` 的 `port` |
| 3 | 找不到 Node | 提示去 nodejs.org 安装 |

`launch-server.ps1` 先探测 `GET /api/ping`：
- 返回 `{app:'renamer-web'}` → 直接 `exit 0`，不重复起进程；
- 端口有人监听但身份不符 → 先等 8×200ms（可能是自己的宿主还在启动），仍不符才判为占用；
- 无人监听 → `Start-Process -WindowStyle Hidden` 起 Node，轮询 HTTP 身份（不是只探端口）最多 15 秒。

**两个容易漏的细节**：
- 版本管理器（nvm / volta / fnm）的 `node` 是 `.cmd` 垫片，`CreateProcess` 不能直接执行 → 用 `cmd.exe /c "&lt;shim&gt;" server\index.mjs` 包一层。
- `-WindowStyle Hidden` 加在 `powershell` 调用上，第二个黑窗才不会闪；`.cmd` 自身的窗口在 `exit /b 0` 时立即消失。

日志写在项目内 `.tmp\logs\{server.out,server.err}.log`，比 `%APPDATA%` 更容易让用户找到。
`/api/ping` 同时暴露 `pid` 与 `clients`，前者用于确认没有重复起宿主，后者用于确认标签页真的连上了（见第 9 条）。

## 11. 空闲退出依赖 SSE 断连

**做法**：浏览器标签页关闭 → SSE 连接断开 → `clients.size === 0`；空闲计时器（默认 120s）
在「无连接 + 无任务」时 `process.exit(0)`。调试时用 `RENAMER_WEB_NO_IDLE=1` 关掉。

注意：只开页面不操作不会退出（SSE 还连着），这是刻意的——用户可能就挂着。

---

## 12. 虚拟滚动的两个细节

- 行容器用 `position:absolute` + `transform: translateY(first*rowH)`，外层放一个只有高度的
  spacer 撑出滚动条；滚动只重绘当前窗口，不重建整张表。
- 视口外只保留 `BUFFER=8` 行，实测 1440×900 下 DOM 只有 **27~36 个 `.grid-row` 节点**（1 万条数据）。

服务端同样做了取舍：`view` 计算出的索引数组**按 revision 缓存**，滚动时只做切片，
不重复过滤。

## 15. 抽屉遮挡比对区，改成左栏内联编辑器

**现象**：规则 Drawer 从右侧覆盖文件表，配置规则时看不到右侧的新文件名，改一次要点一次关闭。

**原因**：Drawer 的定位模型天然假设「编辑是临时任务」，但重命名工具的核心循环是
「改规则 → 看结果 → 再改」，编辑器必须与结果同屏。

**做法**：主区改成 `360px minmax(0,1fr)` 双栏；规则列表下方留 `inspector` 区，选中规则时
就地展开。规则类型只在新增时显示（编辑时隐藏），避免误切换类型丢字段。UI 验收直接断言
`inspector.right <= files.left`，不靠肉眼。

## 16. 快速搜索/切 Tab 时旧响应覆盖新结果

**现象**：连续打字或快速切换视图，`/api/files` 乱序返回，旧查询的 `rows` 盖住新查询。

**做法**：两层保护：

1. **AbortController 管道**：每次 `gridReset()` 中止上一代文件窗口请求；每次新预览中止
   上一次预览。被 abort 的请求不弹 toast、不写状态。
2. **revision 版本戳**：服务端每次预览/改名都递增 `state.revision`，前端丢弃
   `data.revision < state.revision` 的回执；预览还有单调递增的 `previewSeq`，防止
   「取消已发出但服务端已算完」的乱序回包。

只做防抖不够：240ms 防抖只能减少请求，不能保证已发出的请求按顺序落地。

## 17. 整行变绿看不出改了什么

**做法**：`public/diff.mjs` 用 LCS 做字符级 Diff，返回相邻合并后的 `same/del/ins` 操作。
先剥公共前缀/后缀，再做中间段 DP；典型 20~60 字符文件名只跑很小的矩阵。`<del>` 用
浅红+中划线，`<ins>` 用浅绿+下划线。10k Diff 性能断言放在 `test/run.mjs`，避免以后
为了「更聪明的词级对齐」引入大依赖。

## 18. 冲突修复的 `guard < 500` 是假安全感

**现象**：600 个同名目标时，`_1.._500` 都失败后循环直接退出，剩下的行仍是冲突，且
每行都从 `_1` 重新探测，O(n²) 次文件系统调用。

**做法**：

- 每个目录 `readdirSync` 一次，建立大小写折叠的 `Set`；不再对每个候选做 `existsSync`。
- 批次内维护 `claimed` 占用表；unchanged 行不参与占位（它本来就在目标名上）。
- 每个前缀维护 `nextSuffix` 游标，后续同名项从上次位置继续；没有硬编码上限，候选名
  由「有限磁盘集合 + 有限批次集合 + 无限整数后缀」保证必然终止。
- 追加后缀后同步更新 `newBase/newExt/newPath`，否则落盘阶段会拿到旧的拆分结果。
- 候选长度超过 255 时从主名尾部收缩，避免「修完冲突又变成非法文件名」。

## 19. Windows 锁不是永久失败，但也不能无限重试

**做法**：只对 `EPERM` / `EBUSY` 做最多 3 次、间隔 50ms 的重试；`ENOENT` 等确定性错误
立即失败并回滚。重试实现支持注入 `rename`，测试不会真的和资源管理器抢文件句柄。重试
放在两阶段事务的每一次 rename 上，回滚和撤销同样受益。

---

## 20. append 扫描后旧视图缓存

**现象**：`mode:'append'` 且 `autoPreview:false` 时，新条目已经进入 `state.items`，但
`state.revision` 没变，`viewIndexes()` 的缓存继续返回旧索引；前端看到的总数仍是上一次的。
只有等下一次预览或改名碰巧 `bump()` 才恢复。

**做法**：扫描阶段统计真正新增的条目数；`added > 0` 就立即 `bump()`，不依赖预览来顺手
清缓存。响应里的 `added` 也从「扫描到的条目数」改成「实际新增数」，重复追加不再虚报。
回归用真实 HTTP 子进程：先查 `view=all` 建缓存，再 append 一个文件，断言总数从 1 变 2。

## 21. 子串式 Origin 校验不是同源校验

**现象**：`origin.includes('127.0.0.1:8758')` 会把 `http://127.0.0.1:8758.evil.test`
当成自己；本地重命名器接受远程页面的写请求，属于高危 CSRF 口子。

**做法**：Host 与 Origin 都解析成 URL 后做精确匹配：端口必须等于监听端口，Origin 的
scheme/host/port 必须与 Host 完全一致；无 Origin 的 CLI/curl 请求放行，写操作仍受 Host
限制。回归测试同时覆盖合法 loopback、错误端口、外部域名和带后缀的伪造 Origin。

## 22. 文件夹只能单选，二级目录里的文件消失

**现象**：`FolderBrowserDialog` 只能返回一个 `SelectedPath`；另外 Windows 的 junction /
符号链接在 Node 的 `Dirent` 里不是 `isDirectory()`，普通递归会在链接这一层静默断掉，
链接下面的文件全部看不到。

**做法**：

- 文件夹选择改用 `IFileOpenDialog`，设置 `FOS_PICKFOLDERS` + `FOS_ALLOWMULTISELECT`
  + `FOS_FORCEFILESYSTEM`，直接通过 `GetResults()` 取多个绝对路径；保留
  `FolderBrowserDialog` 作为 C# 编译失败时的单目录回退。
- `scanPaths` 对每个目录先 `realpath()`，用大小写折叠的 `visitedDirs` 防循环；遇到
  `isSymbolicLink()` 时 `stat()` 目标，目录继续递归，文件正常加入。这样 junction 下的
  文件能被扫描到，环状链接也不会无限递归。
- 扫描结果增加 `skippedDirs`，前端对无法读取/无权限目录给出提示，不再完全静默。
- 导入成功后自动切到「全部」视图：默认的「关注项」只显示改动，导入后没有规则时
  会看起来像“文件没进来”；「全部」能立即看到并勾选所有层级文件。
- 文件栏增加「包含子文件夹」开关，默认开启；关闭时只扫描所选目录当前层。
- 回归测试构造 `root/level1/level2/level3` 以及一个指向外部目录的 junction，断言两个
  来源的文件都在扫描结果里；UI 验收通过 mock 选择框实际走完扫描并断言 4 行、视图为
  「全部」。

## 23. 元标签不能靠全局字符串替换

**需求**：ReNamer 的 Meta Tags 允许在 Replace / Insert 等规则里插入日期、体积、父文件夹名
等动态值，例如 `[:Date_Now:]_[:File_FolderName:]`。

**做法**：

- 统一约定 `[:Tag_Name:]`，大小写不敏感；未知标签原样保留，避免拼错后静默删文本。
- 标签定义集中在 `server/renamer/metatags.mjs`，API `/api/rule-types` 同时返回
  `metaTags` 给 UI；前端不维护第二份列表。
- **按字段 opt-in**：只有 RULE_META 中标记 `metaTags: true` 的字段才展开。正则 pattern、
  Script 源码、List 内容、日期格式串不会被误替换。
- 展开发生在每次 `apply()` 内，使用当前规则链的 `{base, ext}` 与同一个 `context.now`；
  因此 `Date_Now` 在一次预览中稳定，`File_Name` 反映前序规则的结果。
- 文件体积/时间通过 item 元数据优先、`statSync` 兜底；和 UserInput 的 `[:size:]` 行为一致。
- UI 的「插入元标签」只在光标处插入 token，不直接插入当前值，保证后续换文件仍动态求值。
- 回归覆盖：文件夹名替换、`File_Size`、`File_DateModified`、`Date_Now` 格式、未知标签保留。
